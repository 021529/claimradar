# ML 백본 보강 후 실험 재실행 결과 (2026-08-30)

`src/scoring/ml_model.py`가 5개 수치형 피처 단독 RandomForest에서 **범주형
One-Hot + class_weight='balanced'**(`src/scoring/features.py`가 정의하는 23개
피처)로 바뀌면서, 이 피처·불균형처리 조합으로 스코어를 만드는 모든 실험의
절대 수치가 달라졌다. 이 문서는 제출 문서에 인용된 6개 실험을 새 모델
기준으로 재실행하고 옛 수치와 나란히 비교한다.

**방법론 — 배포 앱과 정확히 일치**: 최초 재실행에서는 기존 24건 스크립트들이
API 비용 절약을 위해 써 온 휴리스틱 LLM 폴백(`_heuristic_analysis`)을 그대로
썼는데, 이 값이 배포 앱이 실제 Claude 호출로 얻는 값과 달라 **문서 수치와
배포 화면 수치가 어긋나는 문제**가 있었다. 이를 해결하기 위해
`data/processed/sample_claims_24case_llm_cache.csv`(300건 버전에 이미 쓰던
방식과 동일)를 `data/sample/sample_claims.csv`에 영구 병합하고, 4개 스크립트
모두 이 캐시값을 직접 쓰도록 바꿨다. **아래는 이 수정을 반영한 최종 수치이며,
배포 앱 화면에서 관찰되는 수치와 정확히 일치함을 AppTest로 직접 검증했다**
(baseline 순회수액 109,950 / 개선율 +45.5% — 앱에서 관찰된 값과 동일).
API 추가 호출 0건 (기존 캐시 재사용).

## 2. lambda_sweep (24건) — 계단 구조 재확인

**옛 모델**: 4단계 계단, λ=30,000~500,000 구간, 40%→60%→80%→100%, λ=480,000에서 수렴.

**새 모델(실제 LLM 캐시 기준, 1,000 단위까지 정밀 재탐색)**: 여전히 4단계
계단이지만, 구간이 훨씬 앞당겨졌다.

| 구간 | λ 범위(정밀) | 고위험 커버리지 | 최적화 순회수액 |
|---|---|---|---|
| 회수액 우선 | 0 ~ 42,800 | 50.0% | 160,000 |
| 전환 1단계 | 43,000 ~ 65,000 | 66.7% | 140,150 |
| 전환 2단계 | 67,000 ~ 79,000 | 83.3% | 119,950 |
| 고위험 차단 우선 | 80,000 이상 (500,000까지 평평함 확인) | 100.0% | 109,950 |

- λ=66,000 정확히 한 지점만 net=130,500으로 튀는 불안정한 예외가 있어(양쪽
  67,000/65,000은 각각 119,950/140,150으로 안정적) 프리셋 대표값 선정에서 제외했다.
- **100% 수렴점이 λ=480,000 → λ=80,000으로 6분의 1 수준으로 당겨졌다.**
- 옛 모델의 "0~25,100에서는 전혀 안 움직인다"는 특징도 사라짐 — λ=43,000부터
  이미 baseline(100%) 대비 하락한 트레이드오프가 시작된다(회수액 우선 구간
  자체는 42,800까지 유지).

### 프리셋 3종 — 최종 결정

| 프리셋 | 옛 값 | 새 값 | 근거 |
|---|---|---|---|
| 회수액 우선 | 0 | **0** (유지) | 항상 λ=0이 순회수액 극대화 |
| 균형 | 90,000 | **50,000** | 전환 1단계(순회수액 140,150) — 회수액 우선(160,000)과 고위험 차단 우선(109,950)의 산술 중간값(134,975)에 가장 가까워 "균형"이라는 이름에 부합 |
| 고위험 차단 우선 | 480,000 | **80,000** | 100% 커버리지 도달 최소 λ |

**"균형"을 전환 2단계(119,950, λ=70,000)가 아닌 1단계(140,150, λ=50,000)로
정한 이유**: 세 프리셋의 순회수액이 160,000 / 140,150 / 109,950으로 고르게
분포해 "균형"이 시각적으로도 두 극단의 중간처럼 보인다. 전환 2단계를 쓰면
119,950으로 고위험 차단 우선(109,950)과 8.3%밖에 차이 나지 않아 "균형"이라는
이름과 실제 결과가 어긋나 보일 위험이 있었다. (참고로 전환 1단계 vs 고위험
차단 우선 자체는 순회수액 −8.3%p·커버리지 +16.7%p로 유의미하게 다른 두
정책이다.)

### UI 슬라이더 상한 — 500,000 → 150,000로 조정

100% 수렴점(80,000) 기준으로 500,000은 슬라이더의 84%가 결과 변화 없는
구간이 된다. **실험 자체(0~500,000 스윕)는 그대로 유지**하되(그 범위까지
실제로 돌려서 평평함을 확인한 사실 자체는 바뀌지 않음), **UI에 노출하는
슬라이더 상한만 150,000으로 낮췄다** — 수렴점(80,000)의 약 2배로, 수렴
이후 평평한 구간을 일부 보여주면서도 슬라이더 대부분이 무의미해지는 것은
피한다. 과거 "범위를 너무 좁게 잡았다가(0~25,100) 트레이드오프를 놓쳐서
500,000까지 넓혔다"는 이력이 있어(README 참고), 여유 마진을 두는 쪽을 택했다.

### `_lambda_regime` 3구간 경계 재조정

`app.py`의 λ 구간 안내 문구가 3구간으로 나뉜다:

| 구간 | λ 범위 |
|---|---|
| 회수액 우선 구간 | λ < 43,000 |
| 균형(전환) 구간 | 43,000 ≤ λ < 80,000 |
| 고위험 차단 우선 구간 | λ ≥ 80,000 |

(기존 코드는 "λ≤0"을 회수액 우선 구간의 경계로 썼으나, 실제로는 λ=1~42,800도
baseline과 완전히 동일한 결과라 43,000으로 정정했다.)

## 4. greedy_vs_ortools_comparison

| | 옛 모델 | 새 모델(실제 LLM) |
|---|---|---|
| 최대 gap | 6.22% (λ=300,000) | **3.69% (λ=150,000)** |
| 극단 λ에서 그리디 커버리지 | 60%에서 정체 | **83.3%→66.7%로 오히려 하락** (λ≥150,000) |
| OR-Tools 커버리지 | 100% 유지 | 100% 유지 |

- **파라독스가 더 뚜렷해짐**: 옛 모델은 그리디가 특정 커버리지에서 "정체"했을
  뿐이지만, 새 모델(실제 LLM)에서는 λ가 커질수록 그리디의 커버리지가 오히려
  **악화**된다(83.3%→66.7%) — 단위시간당 효율 그리디가 λ가 클수록 더 나쁜
  근시안적 선택을 한다는 뜻. "그리디로 충분하다"는 반박에 대한 근거가 더 강해짐.

## 5. hierarchical_filtering — 최종 프리셋(λ=50,000) 기준 재확인

**λ=0**: 필터링 강도와 무관하게 baseline 순회수액/커버리지 불변(구조적으로
당연함). 상위 30%(호출 70.8% 절감)까지도 재현율 100%·순회수액 손실 0%.

**λ=50,000(최종 "균형" 프리셋)**:

| 필터링 강도 | 호출 절감율 | 재현율 | 순회수액 Δ | 커버리지 Δ |
|---|---|---|---|---|
| 상위 10% | 91.7% | 33.3% | +0.0% | +0.0%p |
| 상위 20% | 83.3% | 66.7% | -6.9% | +16.7%p |
| 상위 30% | 70.8% | 100.0% | -6.9% | +16.7%p |
| 상위 50% | 50.0% | 100.0% | +0.0% | +0.0%p |
| 상위 100%(전체) | 0.0% | 100.0% | +0.0% | +0.0%p |
| 임계값 0.3 | 37.5% | 100.0% | +0.0% | +0.0%p |
| 임계값 0.5 | 45.8% | 100.0% | +0.0% | +0.0%p |
| 임계값 0.7 | 62.5% | 100.0% | -6.9% | +16.7%p |
| 임계값 0.85 | 95.8% | 16.7% | +0.0% | +0.0%p |

- **9개 필터링 강도 중 6개(상위 10/50/100%, 임계값 0.3/0.5/0.85)가 순회수액
  손실 0%** — 91.7% 절감(상위 10%)에서도 손실이 없다.
- 나머지 3개(상위 20/30%, 임계값 0.7)는 순회수액이 −6.9% 줄지만, 대신
  고위험 커버리지가 +16.7%p **올라간다** — "더 나빠짐"이 아니라 다른(오히려
  위험회피적) 트레이드오프 지점으로 이동한 것.
- (참고: 앞서 최초 보고에서는 아직 확정되지 않은 λ=66,000/70,000 후보값
  기준으로 "안전구간이 좁고 비단조적"이라 보고했는데, 최종 확정된 λ=50,000
  기준으로는 오히려 준수한 결과가 나왔다 — λ 대표값 선택 자체가 이 실험의
  결론에 영향을 준다는 뜻이므로, 제출 문서에는 반드시 "λ=50,000(균형 프리셋)
  기준"이라고 명시해야 한다.)
- 너무 공격적으로 걸러도(임계값 0.85, 95.8% 절감) 재현율이 16.7%까지 급락하는
  것은 옛 결론과 동일 — 그럼에도 순회수액 손실은 0%인 것은 24건이라는 작은
  표본 크기에서 우연히 나타난 결과일 수 있어, "재현율이 낮아도 항상
  안전하다"고 일반화하지 않는다.

## 요약

- **결론이 뒤집힌 항목은 없음** — OR-Tools 우위, 그리디의 구조적 한계(오히려
  더 뚜렷해짐), "λ=0에서는 필터링이 무해"라는 정성적 결론은 모두 유지, 대부분
  더 강해짐.
- **프리셋 3종 최종 확정**: 0 / **50,000** / **80,000** (슬라이더 상한 **150,000**),
  `_lambda_regime` 경계는 43,000 / 80,000.
- **문서 수치 = 배포 앱 화면 수치 일치를 AppTest로 직접 검증 완료**
  (baseline 109,950 / +45.5%, 배포 앱과 정확히 동일).
- 제출 문서에서 구 수치를 인용한 부분은 이 문서의 "새 모델(실제 LLM)" 값으로 교체 필요.
